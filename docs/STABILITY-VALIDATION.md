# 稳定性修复验证 · 2026-09-05

## 目标与范围

提高 quick / standard 的可靠完成效率。本轮修复停滞识别、模型故障暂停、
会话销毁后的 CHECK 收尾;不改变冻结验收标准、判定强度或升级阈值。

## 离线回归

测试边界为真实 Runtime 接收宿主事件,以及 core 的纯函数判定。

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 每轮回复记账后触发 settled | 连续三轮都推动,费用记账冒充进展 | 只推动一次,再次停滞告警 |
| `402 budget_exceeded` 后 settled | 再次推动不可用模型 | 显示原因和恢复方式,成功回复后解除暂停 |
| ACT 中模型错误或人工中止 | 可能把未完成的诊断当作完成 | 相位与尝试次数不变 |
| CHECK 触发换会话,旧 ctx 失效 | finally 刷新 UI 抛 stale 错误 | 旧实例停止副作用,接力状态保留 |
| 脚本执行期间销毁会话 | 缺少实例生命周期保护 | 迟到结果不提交,新实例可恢复到 DO |

前三个主要故障分别完成失败测试 → 修复 → 通过。
模型服务暂停只限制本扩展的自动推动,不修改 pi 自身的网络重试策略。
未给已启动的 hard 验证脚本新增强制终止机制;其迟到结果会被丢弃。
