# 出题

题库跑空了、或者新机制刚合进主线(scout 就是这么来的),就得出新题。写进 `docs/EXAMS.md`。

## 题从哪来:哑火清单,不是功能清单

**别从「这个功能该测了」出发** —— 那会出一堆考同一条已经压过的路径的题。
从「哪条路径最久没被真机压过」出发,查法:

- `SNAPSHOT.json` 的额度字段常年是 0(`scoutRounds` / `spikesRun` / `defineAsks`)
- `LOG.md` 里反复出现同一条 WARN,而没人处理过
- `toolsForPhase()` 里有工具从没在任何 `profile.json` 的工具册里出现过
- 记分板上判过 **未判** 的行 —— 那条机制到现在还是没被压到

## 四条判据

**一题一机制。** 同时考三样,失败了分不清是哪一样坏的。

**机制必须是通关的必经之路。** 这是出题最容易错的地方:
E2 能考 scout,是因为写那份计划真的需要四件互不依赖的事实;
如果串行读两个文件就够了,那 scout 没触发**不算哑火,是题出错了**。
写完先自问:不动用这个机制,能不能把这题做出来?能,就重出。

**题面是考场仓库里真实、合理的活。** 编造的任务模型能察觉不对劲,行为就不自然了 ——
量到的就不是它平时的样子。

**「不通过说明什么」比「通过」更重要。** 前者是改动的来源。
写不出来的题不收进题库 —— 说明你还不知道它失败了要改什么,那这一轮观测注定白跑。

## 一道题的形状

抄现有任意一道的结构:标题、题面代码块、档与成本、考什么、通过、不通过说明什么。

题面写成可直接粘的一行 `/mission new …`(或 `/mission quick …`),带上 `--tier=`。
**收进题库前先过一遍真的 `parseArgs`**,确认子命令、档位、goal 正文都干净:

```bash
node --experimental-strip-types -e '
import("./src/commands.ts").then(({parseArgs}) => console.log(parseArgs(process.argv[1])))
' "new <你的题面> --tier=standard"
```

成本标出来,故意做不到的题(像 E5)排在最后 —— 它烧的 token 最多,收益只有"失败怎么收场"这一条。

## 排序

题库按「哪条路径最久没被真机压过」排,不按难度。新题插进去时也按这条,
不是往末尾追加 —— 追加等于让它排在一堆已经压过的路径后面,永远轮不到。
